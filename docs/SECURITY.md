# Security and evidence boundaries

Single local user; loopback-only Waitress service. No authentication for other OS users: protect the OS account and data directory. No public/LAN deployment is supported. The browser validates Host, same-origin POSTs, per-session CSRF tokens, strict cookies, and a no-script CSP. Source HTML is escaped, never served as executable snapshots; raw files are attachment downloads. Exports escape all source/user content and contain no scripts or remote assets. Originals remain untrusted files when opened in external software.

Source fetching requires exact approved hosts. It rejects credentials in URLs, non-HTTP(S), nonstandard ports, private/link-local/loopback/reserved/multicast addresses and unsafe redirects. Direct connections validate all DNS answers and pin the selected public IP; HTTPS validates the original hostname and certificate. A managed/trusted proxy is a deliberate alternative (`ISM_TRUSTED_PROXY=1`) because a CONNECT proxy owns DNS resolution. In that mode the proxy must enforce public-address destinations and redirect policy. This option must not be enabled for an arbitrary proxy. Cloud destination allowlists cannot be bypassed by direct sockets or alternate endpoints.

Fetches use a descriptive user agent, two-second minimum per-domain spacing (or slower robots rules), at most two attempts for network exceptions, 20-second socket timeout, 45-second read budget plus an in-progress socket read, 15 MiB body limit, at most five redirects, and persisted Retry-After cooldowns. Redirect evidence is reported but does not silently replace a source identity. Robots denials/errors are failures. Only public read requests are made; no login/CAPTCHA bypass.

Extraction runs in a separate process with a 25-second wall deadline; POSIX additionally limits CPU and address space. Windows has the wall deadline but lacks the POSIX memory limit. PDFs are limited to 400 pages and require text on every page; no OCR, script execution, or external content retrieval. XML uses defusedxml. Large comparison previews are bounded; raw evidence remains accessible. Failure captures can be retained without becoming baselines. SQLite update/delete triggers protect observed versions; hashes support integrity checks, not proof of a government publication date or cryptographic authenticity of the government's content.

Runtime files and credentials are outside Git. Public evidence, private reviews, and delivery settings occupy separate tables; private notes are clearly labelled in exports. DPAPI email credentials and session keys are excluded from backups. SMTP uses verified TLS/STARTTLS, never plaintext authentication. No telemetry, AI calls, third-party uploads, government-portal access, or client records.

Backup uploads do not extract arbitrary paths. Restore accepts only the two expected ZIP members, bounded sizes/compression, a matching checksum, exact application schema, database integrity and evidence hashes. It requires stopped UI/checker/delivery processes, creates a safety backup, disables email, and holds unsent queue items. These controls do not make untrusted backups a secure source of truth: obtain backups from your own trusted archive.
